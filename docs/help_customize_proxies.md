# آموزش شخصی‌سازی پروکسی‌ها

در این آموزش سه کار رایج را با **ویرایشگر پروکسی** پنل انجام می‌دهیم:

1. [اضافه کردن یک لینک اشتراک (ساب) دیگر فقط برای یک کاربر خاص](#آموزش-۱-لینک-ساب-اختصاصی-برای-یک-کاربر)
2. [فرستادن ترافیک یک کاربر خاص از یک خروجی (اوت‌باند) خاص، مثلاً WARP](#آموزش-۲-خروجی-اختصاصی-برای-یک-کاربر)
3. [فرستادن کل ترافیک خروجی سرور به جای اینترنت مستقیم، به یک پروکسی دیگر (مثلاً SOCKS)](#آموزش-۳-خروجی-سرور-از-طریق-یک-پروکسی-ساکس)

## پیش از شروع: فیلد «Extra Params» کاربر

هر کاربر یک فیلد JSON به نام **Extra Params** دارد (در صفحه ویرایش کاربر). هر کلیدی که اینجا بنویسید، در قالب‌های پروکسی با این نام در دسترس است:

```jinja
ctx.user.extra.<نام کلید>
```

اگر کاربری آن کلید را نداشته باشد، مقدارش خالی است. پس با یک `if` ساده می‌توانید تغییر را فقط برای کاربرانی اعمال کنید که آن کلید را دارند.

> در قالب‌هایی که همه کاربران را با هم می‌سازند (مثل قالب‌های سمت سرور)، به جای `ctx.user` روی `ctx.users` حلقه می‌زنید و از `u.extra.<نام کلید>` استفاده می‌کنید.

</div>

## آموزش ۳: خروجی سرور از طریق یک پروکسی ساکس

**هدف:** ترافیکی که سرور به‌طور معمول مستقیم به اینترنت می‌فرستد، به یک پروکسی دیگر (مثلاً یک سرور SOCKS5 خارج) فرستاده شود.

به **تنظیمات ← ویرایشگر پروکسی ← قالب‌ها** بروید، قالب اوت‌باندهای سرور را باز کنید و **محتوای سفارشی** (override) آن را فعال کنید:

| هسته | قالب |
|---|---|
| Xray | `xray/server/base/outbounds` |
| Hiddify-core (sing-box) | `hiddify-core/server/base/outbounds` |

در این قالب، خروجی مستقیم (`freedom`) را پیدا کنید و **نوع آن را از direct به socks تغییر دهید**. tag را تغییر ندهید تا همه قانون‌های روتینگ که به `freedom` اشاره می‌کنند، از این به بعد از پروکسی ساکس رد شوند.

**Xray** — قبل:

</div>

```json
{"tag": "freedom", "protocol": "freedom"},
```

<div dir="rtl">

بعد:

</div>

```json
{
  "tag": "freedom",
  "protocol": "socks",
  "settings": {
    "servers": [
      {
        "address": "1.2.3.4",
        "port": 1080,
        "users": [{"user": "USERNAME", "pass": "PASSWORD"}]
      }
    ]
  }
},
```

<div dir="rtl">

**Hiddify-core / sing-box** — قبل:

</div>

```json
{
    "tag": "freedom",
    "type": "direct"
},
```

<div dir="rtl">

بعد:

</div>

```json
{
    "tag": "freedom",
    "type": "socks",
    "server": "1.2.3.4",
    "server_port": 1080,
    "version": "5",
    "username": "USERNAME",
    "password": "PASSWORD"
},
```

<div dir="rtl">

اگر پروکسی ساکس شما نام کاربری و رمز ندارد، بخش `users` را در Xray و فیلدهای `username` و `password` را در sing-box حذف کنید.

ذخیره کنید و **اعمال تنظیمات** را بزنید.

### نکته‌ها

- **خروجی `direct` را دست نزنید.** با همین کار همیشه یک راه برای اینترنت مستقیم دارید. با آموزش ۲ هم می‌توانید کاربرانی را که نباید از پروکسی رد شوند، با `"outbound": "direct"` مستقیم بفرستید.
- در Xray، یک قانون ترافیک محلی سرور (`127.0.0.1` روی پورت‌های 443، 80 و 53) را به `freedom` می‌فرستد. بعد از این تغییر، در قالب `xray/server/base/route` برای این قانون `"outboundTag"` را از `"freedom"` به `"direct"` تغییر دهید؛ در غیر این صورت ترافیک محلی سرور هم به پروکسی ساکس می‌رود و کار نمی‌کند.
- اگر فقط می‌خواهید **بخشی** از ترافیک (مثلاً یک کاربر یا چند سایت) از پروکسی ساکس برود، به جای تغییر `freedom` یک اوت‌باند جدید با tag دلخواه (مثلاً `"tag": "my-socks"`) اضافه کنید و با آموزش ۲ یا یک قانون روتینگ، ترافیک مورد نظر را به آن بفرستید.
- برای امتحان، با یک کاربر وصل شوید و IP خود را بررسی کنید؛ باید IP سرور ساکس را ببینید.

</div>

## آموزش ۱: لینک ساب اختصاصی برای یک کاربر

**هدف:** کانفیگ‌های یک لینک اشتراک دیگر (مثلاً از یک پنل یا سرور دیگر) فقط به اشتراک همین کاربر اضافه شود.

### مرحله ۱: لینک را در Extra Params کاربر بنویسید

از **مدیریت کاربران**، کاربر را ویرایش کنید و در فیلد **Extra Params** این را بنویسید:

</div>

```json
{
  "sub": "https://your-sub/for_user"
}
```

<div dir="rtl">

### مرحله ۲: پروکسی «Additional Config» را ویرایش کنید

1. به **تنظیمات ← ویرایشگر پروکسی ← پروکسی‌ها** بروید.
2. پروکسی داخلی **Additional Config** را باز کنید. این پروکسی به‌صورت پیش‌فرض غیرفعال است؛ آن را **فعال** کنید.
3. در تب **کلاینت**، روی هسته مورد نظر (مثلاً `sublink`) **محتوای سفارشی** را فعال کنید تا بتوانید قالب را ویرایش کنید.
4. آدرس‌های نمونه (`example.com`) را حذف کنید و به جای آن از `ctx.user.extra.sub` استفاده کنید:

**هسته `sublink` (لینک‌های اشتراک متنی):**

</div>

```jinja
{% if ctx.user.extra.sub %}
  {% set additional_configs = download("txt", "1h", ctx.user.extra.sub) %}
  {% for conf in additional_configs if conf %}
{{ conf }}
  {% endfor %}
{% endif %}
```

<div dir="rtl">

**هسته `hiddify-core` (sing-box):** اینجا لینک باید خروجی JSON بدهد:

</div>

```jinja
{% set additional_configs = download("json", "1h", ctx.user.extra.sub) if ctx.user.extra.sub else [] %}
{% block outbounds %}
  {% for conf in additional_configs if conf %}
    {% for outbound in remote_proxy_outbounds(conf, "hiddify-core") %}
      {{ outbound | tojson }},
    {% endfor %}
  {% endfor %}
{% endblock %}

{% block endpoints %}
  {% for conf in additional_configs if conf %}
    {% for endpoint in remote_endpoints(conf) %}
      {{ endpoint | tojson }},
    {% endfor %}
  {% endfor %}
{% endblock %}
```

<div dir="rtl">

5. ذخیره کنید و اشتراک همان کاربر را باز کنید. کانفیگ‌های لینک دوم باید به آن اضافه شده باشند.

### نکته‌ها

- `download(نوع، زمان کش، آدرس۱، آدرس۲، ...)`
  - **نوع:** `txt` یا `json` یا `yaml`.
  - **زمان کش:** مثل `1h` یا `30m` یا `90s`؛ اگر `0` بگذارید، هر بار دوباره دانلود می‌شود.
  - می‌توانید چند آدرس بدهید و خروجی یک لیست است، به ترتیب همان آدرس‌ها.
- اگر دانلود یک آدرس خطا بدهد، به جای آن `None` برمی‌گردد و با `if conf` نادیده گرفته می‌شود؛ پس خراب بودن لینک دوم، اشتراک اصلی کاربر را خراب نمی‌کند.
- برای هسته `sublink`، لینک باید **متن ساده** برگرداند (هر کانفیگ در یک خط)، نه base64.
- User-Agent درخواست همان User-Agent برنامه کاربر است؛ پس سرور دوم همان فرمتی را می‌دهد که برنامه کاربر انتظار دارد.
- اگر بخواهید برای **همه** کاربران یک ساب دیگر اضافه شود، کافی است آدرس را با `ctx.user.uuid` بسازید:

</div>

```jinja
download("txt", "1h", "https://other-panel/sub/" ~ ctx.user.uuid)
```

## آموزش ۲: خروجی اختصاصی برای یک کاربر

**هدف:** ترافیک یک کاربر خاص به جای اینترنت مستقیم سرور، از یک اوت‌باند دیگر (مثلاً WARP) خارج شود.

### مرحله ۱: اوت‌باند را در Extra Params کاربر بنویسید

</div>

```json
{
  "outbound": "WARP"
}
```

<div dir="rtl">

> مقدار باید **دقیقاً** برابر با `tag` یکی از اوت‌باندهای سرور باشد (بزرگی و کوچکی حروف مهم است). اوت‌باندهای پیش‌فرض سرور این‌ها هستند: `freedom` و `direct` (اینترنت مستقیم)، `WARP` و `blackhole` (در sing-box: `block`). اگر اوت‌باند جدیدی ساخته‌اید (آموزش ۳ را ببینید)، tag همان را بنویسید.

### مرحله ۲: قانون روتینگ را اضافه کنید

به **تنظیمات ← ویرایشگر پروکسی ← قالب‌ها** بروید و قالب روتینگ سرور را باز کنید. قالب‌های داخلی قفل هستند؛ برای ویرایش، **محتوای سفارشی** (override) قالب را فعال کنید:

| هسته | قالب |
|---|---|
| Xray | `xray/server/base/route` |
| Hiddify-core (sing-box) | `hiddify-core/server/base/route` |

این قانون را در لیست `rules` قرار دهید؛ **بعد از** قانون‌های DNS و بستن QUIC، و **قبل از** قانون‌های کشور، WARP و قانون آخر. قانون‌ها به ترتیب بررسی می‌شوند و اولین قانونی که با ترافیک جور باشد اجرا می‌شود.

**Xray** (کاربر با `email` شناخته می‌شود که همان UUID کاربر است):

</div>

```jinja
{% for u in ctx.users if u.extra.outbound %}
{
  "type": "field",
  "user": ["{{ u.uuid }}"],
  "outboundTag": "{{ u.extra.outbound }}"
},
{% endfor %}
```

<div dir="rtl">

**Hiddify-core / sing-box** (کاربر با `name` شناخته می‌شود که همان UUID کاربر است):

</div>

```jinja
{% for u in ctx.users if u.extra.outbound %}
{
  "auth_user": ["{{ u.uuid }}"],
  "outbound": "{{ u.extra.outbound }}"
},
{% endfor %}
```

<div dir="rtl">

3. ذخیره کنید و **اعمال تنظیمات** را از صفحه **اقدامات** بزنید.
4. با همان کاربر وصل شوید و IP خود را بررسی کنید (مثلاً در `ipinfo.io`). برای WARP باید IP کلادفلر را ببینید.

### نکته‌ها

- قالب فعلی روتینگ، یک بلوک نمونه برای `extra.outbound` دارد که همه این کاربران را به `WARP` می‌فرستد و به مقدار آن نگاه نمی‌کند. آن بلوک را با کد بالا **جایگزین** کنید.
- اوت‌باند WARP فقط وقتی کار می‌کند که WARP در تنظیمات سرور فعال باشد.
- برای اینکه یک کاربر را از خروجی خاصش برگردانید، کلید `outbound` را از Extra Params او حذف کنید.

</div>

## اگر چیزی کار نکرد

- در صفحه پروکسی یا کانفیگ پایه، **دکمه Validate** را بزنید تا خطای قالب یا JSON را ببینید.
- از صفحه **اقدامات ← مشاهده لاگ‌ها**، لاگ Xray یا sing-box را بررسی کنید.
- برای برگرداندن یک قالب داخلی به حالت پیش‌فرض، **محتوای سفارشی** آن را غیرفعال کنید.

</div>
